# Decisions

Defaults chosen where the brief is silent. Newest last.

| Date | Area | Decision | Why |
|---|---|---|---|
| 2026-11-04 | Repo | `main` created with an initial commit; all work lands by PR. | The repo was empty; PRs need a base branch. |
| 2026-11-04 | Layout | `src/` is the `RBLXShared` ModuleScript (`src/init.luau`); one folder per module. | Same tree whether consumed by Wally or the `Packages/RBLXShared` submodule, so import paths never change. |
| 2026-11-04 | Requires | Inside `src/`, only relative require-by-string (`./X`, `../X`, `@self/X`). | Works identically in Roblox and lune, so every module is unit-testable headlessly. Verified on lune 0.11.1. |
| 2026-11-04 | Purity | No service access or side effects at require time; services, `task`, and `Enum` values are injected with lazy Roblox defaults. | Lune has no `game`, `task`, or `Enum`, and globals cannot be injected into required modules. |
| 2026-11-04 | Tests | Spec files are `tests/**/*.spec.luau`, registered at require time; `lune run tests [filter]`. A committed `T.only` fails CI. | Familiar describe/it shape; filter for quick local loops. |
| 2026-11-04 | Toolchain | rokit (`rokit.toml`) pins rojo 7.7.1, lune 0.11.1, StyLua 2.6.0, Selene 0.31.0, luau-lsp 1.70.0, wally 0.3.2. | Node-free, one install command, same versions locally and in CI. |
| 2026-11-04 | Tools | Lune tools use `.luau` (`lune run tools/upload_assets --all`). | Lune resolves the extension; keeps one source extension in the repo. |
| 2026-11-04 | Wally | `registry` points at `goosepk7/wally-index` (to be created); games use the submodule until then. | Brief §1.2 / §13.3 default. |
| 2026-11-04 | Sim | RNG is xoshiro128** seeded by FNV-1a + splitmix32 in pure 32-bit integer math; golden values pinned in tests. | Identical streams in lune, Studio and live servers; `math.random`/`Random` are not portable. |
| 2026-11-04 | Sim | `rng:fork(label)` derives from the seed, not the stream position. | Adding draws to one player's stream never shifts another's, so sims stay comparable across edits. |
| 2026-11-04 | Sim | Populations use exact quotas (largest remainder), not random sampling, for the 40/40/20 mix. | Removes sampling noise from balance comparisons. |
| 2026-11-04 | Sim | Sims are `sims/**/*.sim.luau` returning a `Sim.Runner` definition; outputs go to `sims/out/` (gitignored, uploaded as a CI artifact). | One definition runs under lune, in Studio, and as an Open Cloud Luau Execution task. |
| 2026-11-04 | Assets | Manifest entries are one file each; size variants are separate entries with a `_<px>` suffix (`icon_wins_64`), resolved by `Assets.variant`. `source` means origin (generated/creator-store/manual); the editable file is `sourceFile`. | Flat list maps 1:1 to uploads; §10 uses `source: "creator-store"`. |
| 2026-11-04 | Assets | Pending assets render as a colored card with the asset name; unknown names warn once (throw in strict mode); `lint` fails CI on unknown literal names. | Brief §1.5: nothing silently breaks. |
| 2026-11-04 | Tools | One Open Cloud client (`tools/lib/opencloud.luau`) for uploads, backups and Luau Execution. Idempotent methods retry 429 (Retry-After), 5xx and network errors; POST/PATCH/multipart retry only 429 and network errors. Keys only from env, never sent to signed CDN URLs. | One place to get auth and retries right; a 5xx on a create may still have created the asset, so retrying it could upload duplicates. |
| 2026-11-04 | Tools | Images upload as Open Cloud `Decal`; the returned id is kept as `decalId` and the wrapped Image id is resolved before `status = "uploaded"`. Failed resolution saves `unresolved` (renders as pending); `tools/resolve_decals` finishes it without re-uploading. Animations are listed for manual Studio upload. | ImageLabels need the Image id, not the Decal id; the Assets API has no animation type. |
| 2026-11-04 | Assets | `Assets.get` returns `""` while an asset is pending or unresolved; the visible placeholder card comes only from `Assets.image` / `Assets.applyImage`. | A content-id property can't hold a placeholder, and `""` renders blank rather than as a broken or wrong image; UI code that wants a visible stand-in uses the image helpers. |
| 2026-11-04 | Test | The DataStore fake's request budgets are opt-in (`enableBudgets`/`setBudget`) and use Roblox's per-minute rates driven by `setNow` time. | Tests that don't exercise throttling shouldn't fail on a frozen clock; tests that do get real decrement, refill and 30x errors. |
| 2026-11-04 | Test | Fake `UpdateAsync` reruns the transform on conflict, with a `setBeforeCommit` hook to inject the competing write. | Session-lock code has to be tested against the race Roblox actually has, where the transform runs more than once. |
| 2026-11-04 | Sim | `Tune.solve` with a `{ min, max }` band bisects for the near edge of the band, not for `meets`. | The far bound can overshoot a band; checking only that end wrongly reported "cannot reach". |
| 2026-11-04 | Owner | Bruce's §13 answers: the age guideline stays 16+ until the games reach about 100 highly engaged players, then it is lifted, so content stays All Ages-safe throughout. "+1 Stilts" and "Evolve a Car" are working names that may change (keep each in one config string). The repos are ours to shape until publish; RBLXShared stays a git submodule for now. The default prices in §6.7 and §7.9 stand. Bruce makes game-page thumbnails, game icons and ad art with ChatGPT at release, so no work goes into those (in-game UI icons are still ours). | Owner decisions, given 2026-11-04 in the project chat. |
| 2026-11-04 | Naming | Modules and signals are PascalCase (`Registry.Flagged`), methods and fields camelCase, and methods that yield end in `Async` (`invokeAsync`, `startAsync`). `Signal` keeps Roblox's PascalCase methods. | Reads like Roblox where it mirrors Roblox, and every yield is visible at the call site. |
| 2026-11-04 | Types | Cross-module types live once in `src/Types`; modules re-export the ones they use (e.g. `Economy.Wallet` is `Types.Wallet`). | One definition per shape, so a field change is visibly a semver-major change. |
| 2026-11-04 | Signal | RBLXShared has its own `Signal` with `RBXScriptSignal`'s surface. Handlers run on their own threads in connection order; a handler error is reported with its traceback and the rest still run. | Same mental model as Roblox events, works under lune, no third-party dependency. |
| 2026-11-04 | AntiExploit | Strikes live in their own module that Net and game systems both report to. Three strikes flags a player for review (no kick by default); the flag log outlives the session (last 100). | Movement and timing checks feed the same count as Net; the Admin panel needs flags for players who already left; a false positive costs nothing. |
| 2026-11-04 | Net | One instance per declared remote, `ReplicatedStorage.RBLXSharedNet.<Namespace>.<Remote>` (RemoteEvent, UnreliableRemoteEvent or RemoteFunction), carrying exactly one payload argument. No server-to-client invokes. | Rate limits, metrics and the kill switch map 1:1 onto remotes; one payload makes extra arguments an exact malformed check; a client that never answers can't stall the server. |
| 2026-11-04 | Net | Inbound order: kill switch, rate limit, argument count, schema, guard, handlers. Server-to-client remotes also get the default limit for (illegal) inbound traffic. | Cheapest checks first, and the limiter runs before anything that can strike, so a flood of bad messages costs at most `burst` strikes plus one flood strike instead of one strike per message (review of #6). |
| 2026-11-04 | Net | Malformed payloads and wrong-direction traffic are strikes. Rate-limit drops strike only for a sustained flood: more than 10 × burst drops on one remote within 10 s, at most one strike per window. | Lag bursts and double-clicks hit limits innocently; malformed data never comes from an honest client. |
| 2026-11-04 | Net | Default limit 10/s with a burst of 20, per player per remote. The client holds itself to the same bucket and `fire` returns false instead of sending. | Generous enough that honest clients never see a drop; tight remotes declare their own. |
| 2026-11-04 | Net | Server-to-client payloads and function responses are checked against their schemas in Studio and tests only (`validateOutgoing`). | Catches server bugs during development at no per-message cost in live servers. |
| 2026-11-04 | Net | Cross-server kill switch: one versioned DataStore key (`RBLXShared` / `Net.KillSwitch`), a MessagingService ping on change, and a 300 s re-read as fallback. Reads use `UpdateAsync` returning nil, which bypasses the DataStore cache. Switched-off remotes carry a `Disabled` attribute for clients. | Works through MessagingService outages and for servers that start later; versions make late or duplicate pings harmless; clients stop sending without a round trip. |
| 2026-11-04 | AntiExploit | Each player gets a strike limit (5 back to back, then one per 5 s): strikes past it still count toward the flag but aren't recorded in `recent` or signalled on `Struck`. | Whatever listens to `Struck` (Analytics, the Admin panel) must not be floodable by one client, whichever path reports the strike; the flag still trips at 3. |
| 2026-11-04 | UI | Token sizes are authored for a 390 pt short edge; `UIScale = clamp(short/390, 0.92, 1.6)`. | 0.92 keeps the smallest tappable control (48 px) at or above the 44 px minimum on small Androids; 1.6 stops tablets/PC turning the HUD into billboards. |
| 2026-11-04 | UI | White label text on saturated fills gets a 1.5 px stroke in the fill's edge color; Warning and Gold fills use Ink text. | The brief's white-on-orange/green fails contrast on its own (about 2:1); the stroke keeps the look and makes it readable. |
| 2026-11-04 | UI | Disabled dimming walks descendants and blends transparency instead of using CanvasGroup. | A CanvasGroup per button is a render target each; too much texture memory on mid-range phones. |
| 2026-11-04 | UI | Kit sounds go through `UI.Hooks`; Audio registers a handler in v0.2. | UI ships in v0.1 before Audio; avoids a circular dependency. |
| 2026-11-04 | UI | `SecondaryEdge` accents (`#4A3DB8` Stilts, `#C77606` Car) and `inkSoft`/`lineDark` were added to the tokens. | The brief gives no edge for secondary fills or Paper buttons; derived by darkening ~22% toward Ink. |
| 2026-11-04 | UI | Icon PNGs are committed next to their SVG sources. | The uploader and owner can work without Python; SVGs stay the source of truth. |
| 2026-11-04 | UI | Gallery stories live in `src/UI/Gallery/Stories.luau` (not `tests/ui_stories.lua`). | `/uigallery` must run in the shipped game; `tests/UI/Stories.spec.luau` checks every variant has a story. |
| 2026-11-04 | UI | Kit `Icon` props take asset names and resolve them through `Assets.applyImage`; Assets placeholder colors come from UI Tokens. | A pending icon shows a visible placeholder instead of a blank square, and the placeholder palette stays on brand with one source of colors. |
| 2026-11-04 | Data | One key per player, `Player_<userId>`, holding `{ data, meta }`. `meta` has the schema version, the session lock, any release request, the load count and the last 100 granted PurchaseIds. Every write is an `UpdateAsync` that tags the user id. | Ownership checks, migrations and receipts all happen atomically in one transform; the user id tag lets Roblox's erasure requests find the key. |
| 2026-11-04 | Data | Session lock timing: each save (autosave every 60 s) refreshes the heartbeat. A lock silent for 600 s belongs to a dead server and is taken at once. A live owner is asked to release (in `meta` and by MessagingService ping) and gets `autosaveInterval` + 30 s (90 s) before the lock is taken; `Store.new` refuses a wait that isn't longer than the autosave interval, and a `lockTimeout` that isn't longer than the wait. The old owner checks ownership in every save transform, so it can't overwrite afterwards. | The ping makes teleports fast. An owner that missed it still sees the `meta` request at its next autosave, which always comes before the wait runs out, so a lost ping costs time, not progress. The lock is only taken from a server that is gone or whose saves are failing, and only what that server couldn't save is lost (never merged). The price: a player rejoining right after a server crash waits up to 90 s for the lock (review of #8). |
| 2026-11-04 | Data | A failed load kicks the player ("we stopped to keep your save safe, nothing was lost") instead of letting them play without saving. A newer schema version, unreadable data and failed migrations are refused and left untouched. | Brief §3.2: a load failure must never look like a new player or overwrite anything. Playing unsaved would lose that session's progress silently. |
| 2026-11-04 | Data | Purchases: the grant and its PurchaseId are saved in one write before `PurchaseGranted`; a grant whose save failed stays in memory, so Roblox's retry saves it instead of granting again. Grants into a profile that is being released are declined for now. | At most one grant per PurchaseId across servers and crashes; Roblox only stops asking once the grant is on disk. |
| 2026-11-04 | Data | Saves store a snapshot taken inside the transform and check that snapshot for storability (NaN, infinity, mixed or sparse tables, non-string keys, Roblox types, over 4 MB). A bad value fails the save with its path; a release still hands the lock back over the last good save. | DataStores error on some of these and silently drop parts of others. Checking the snapshot means what was checked is exactly what gets written. |
| 2026-11-04 | Tools | Profile backups use the Open Cloud data stores v2 API, one NDJSON line per entry, from a daily GitHub Actions job in each game repo (artifacts kept 30 days). Restores are one key at a time, refuse while the player is online, and list purchases made after the backup. | v2 is Roblox's current data stores API and its writes need no Content-MD5. One-key restores keep support fixes small and reviewable. |
| 2026-11-04 | Economy | Reasons are declared up front with a kind. `earn` is multiplied and counts toward lifetime; `grant` (purchases, codes, refunds) is exact, whole and doesn't count toward lifetime unless the reason opts in; `spend` and `adjust` are separate kinds. An undeclared reason or the wrong kind is refused and logged. | "Nothing sells raw height": Stilts height reads lifetime Wins, so Robux grants must never reach it, and a 2x pass must not double a Wins pack. Declared reasons keep the ledger's per-source totals (the 55% income check) clean. |
| 2026-11-04 | Economy | Multiplier sources in the same group add their bonuses; groups multiply (rebirth x pass x event x boost), capped at 100x. A game can make a group multiply its own sources (`multiplyWithin`). | Brief §4: "rebirth x pass x event". Adding within a group keeps stacked passes and boosts readable (2x and VIP +25% is 2.25x, not 2.5x) and stops the total compounding. |
| 2026-11-04 | Economy | Integer currencies carry fractional earnings (`carry`) to the next earn; balances stop at the currency's `max` (at most 1e15), but `lifetime` and `allTime` count every earning in full. | Long-run totals match the multiplier exactly (100 earns of 1 at 1.1x pay 110). The cap guards holdings; progress stats shouldn't stall because a balance is full. 1e15 keeps integer math exact. |
| 2026-11-04 | Economy | Boosts are saved in the wallet and count down only while the player is in a server. Buying the same boost id again adds time. | A 30-minute boost bought before logging off isn't lost; play time is what the player paid for. |
| 2026-11-04 | Economy | Per-player multipliers live apart from the wallet, so they can be set before the profile loads; `bindStore` forgets them when the player leaves. Balances reach clients as player attributes (`Currency_<id>`, `CurrencyLifetime_<id>`, `Boost_<id>`) and, if asked, leaderstats. | A pass check often finishes before the profile loads (or after it). Attributes replicate without a remote and give UI one place to listen. |
